Firebase Setup (5 min)

For real-time team collaboration. Requires a Google account. Free tier is generous.

Step 1. Go to console.firebase.google.com and click "Add project". Give it any name (e.g. binder-qa).
Step 2. Left menu: Build → Realtime Database → "Create database" → pick nearest region → Start in test mode.
Step 3. Top left → Project Settings (gear icon) → General tab → "Your apps" → click Web icon (</>) → set app nickname → Register.
Step 4. The config JSON will be shown. You need these 4 fields: apiKey, authDomain, databaseURL, projectId. Copy the JSON and paste it into the setup modal.
Step 5. Go to Realtime Database → Rules tab and paste this: 
{
  "rules": {
    "sessions": {
      "$sid": { ".read": true, ".write": true }
    }
  }
}
Click Publish. Your session key acts as the security key.
Step 6. IMPORTANT: Open this HTML file via an HTTP server (not file://). Some browsers block Firebase over the file protocol: 
cd folder-with-html
python -m http.server 8000
Then open http://localhost:8000/BOM-PORTAL-TEAM-QA-V2.html

Report downloaded!

Your standalone HTML report is saved. Here is how to publish it so the team can view it in a browser.

Option 1: GitHub Pages (recommended)
1. In your GitHub repository, create a folder like qa-reports/
2. Copy the downloaded HTML file into that folder
3. Commit and push: 
git add qa-reports/
git commit -m "Add QA report"
git push
4. Enable GitHub Pages: repo Settings → Pages → Source: main branch → Save
5. Report URL becomes: 
https://YOUR-USERNAME.github.io/YOUR-REPO/qa-reports/report-name.html
6. Share the URL with the team.
Option 2: View directly on GitHub
Push the HTML file to any GitHub repo. Then wrap the raw URL with htmlpreview.github.io: 
https://htmlpreview.github.io/?https://github.com/USER/REPO/blob/main/path/to/file.html
Simpler than GitHub Pages but slower to load.
Option 3: Any static host
The report is one self-contained HTML file with zero dependencies. Drop it into Netlify, Vercel, Cloudflare Pages, Firebase Hosting, or any web server, and share the URL.
What the report contains
Every module with its full status, every checkbox with who ticked it, every note, every team comment with timestamps, summary counts, testers list. Print-friendly. Zero interactivity, so nothing to break. Read-only.
